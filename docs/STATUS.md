## 팀 결정이 필요한 사항

### 1. 서버: NestJS로 통일 (2026-11-02 합의)

백엔드 담당 태규님과 카카오톡으로 확인했습니다. **서버는 NestJS·PostgreSQL로 통일하고, 푸시 알림만 Firebase FCM을 씁니다.** 태규님이 기존 Firebase 서버 코드를 NestJS로 옮겨 push하기로 했습니다.

NestJS에 아직 없어서 옮겨야 하는 것은 아래와 같습니다. 지금은 Firebase 함수에만 있습니다.

| 옮길 기능 | 내용 |
| --- | --- |
| 안전 호출 | 15초 본인 확인, 30초 뒤 호출 확대, 수락 후 120초 지연 경고, 동료 수락·도착 |
| 푸시 | 기기 토큰 등록, 발송·수신·열람·수락 시각 기록 |
| 사진 | 올리기와 열람 권한 |
| 위험 신고 | 신고, 조치, 다른 동료의 재확인, 익명 처리 |
| 기록 보호 | 해시 연결, 삭제 없이 정정 기록만 추가 |
| 보고서 | 근로 기록, 사고 경위, 월간 집계 PDF |

**앱과 관리자 웹도 바뀝니다.** 지금 둘 다 Firebase에 직접 붙어 있어서 NestJS API를 부르도록 바꿔야 합니다. 앱은 `Repository.kt`, 관리자 웹은 별도 저장소 `jmwshye/safeloop`입니다. 관리자 웹을 누가 옮길지는 아직 정하지 않았습니다.

**순서:** 먼저 태규님이 서버 코드를 옮겨 push합니다. 그다음 앱을 NestJS API에 연결합니다. 요청·응답 형식은 `CONTRIBUTING.md`대로 연결 전에 `backend/API.md`에서 합의합니다. 그동안 앱 화면 작업은 체험 모드에서 계속합니다.

**시연을 폰 2대로 하면 필요한 것**

- 두 폰이 열 수 있는 `https` 서버 주소(클라우드 배포 또는 시연용 임시 주소)
- 서버에서 도는 타이머(서버가 재시작돼도 이어지도록 DB에 저장)
- FCM 푸시 연결
- 시연용 계정 2개, 현장 코드, 안전 동료 배정
- 두 폰 모두 Android

개발 중에는 한 폰의 체험 모드에서 두 사람의 역할을 확인하고, 시연 때만 폰 2대를 씁니다.

**아직 정하지 않은 것:** 제출일, 서버를 올릴 곳, 관리자 웹 담당, 긴급 대응 사진을 선택으로 둘지.

## 코드에서 발견한 문제

`main` 코드의 문제는 최신 앱으로 교체하면 대부분 사라지므로 따로 고치지 않습니다.

| 위치 | 문제 | 처리 |
| --- | --- | --- |
| `main` `MainActivity.kt` | 119 버튼이 위치·로그를 즉시 전송한다고 표시. 실제로는 전화 화면만 열고 `EMERGENCY_119_CALLED`를 사람의 사실로 기록 | 교체로 해결 |
| `main` | 화면이 꺼져도 구조 요청한다는 안내가 있지만 포그라운드 서비스가 없음 | 교체로 해결 |
| `main` | 출근에 점검 3개가 필수라 백엔드·최신 앱의 규칙과 다름 | 교체로 해결 |
| `main` `SafetyModels.kt` | 해시가 메모리에만 있어 앱을 재시작하면 체인이 처음으로 돌아감 | 서버 해시 사용 |
| `main` | 실명, 고정 좌표, 고정 배터리 값이 코드에 있음. 이 저장소는 공개 상태 | 교체 후 이력 처리 여부 결정 |
| `main` | `app/google-services.json`이 공개 저장소에 있음 | Firebase API 키 제한 확인 |
| 관리자 웹 문서 | 사진 오프라인 큐, 동료 대칭 배정, 예정 체크인, 기기 미연결 감지, 보관·삭제 정책 미구현 | MVP 범위 결정 |

Firebase 웹·앱 키는 비밀번호와 달리 앱에 포함되는 값이지만, 보안 규칙과 키 제한이 없으면 악용될 수 있습니다. 서비스 계정 키나 서명 키가 공개되었다는 뜻은 아닙니다.

## 현재 앱에서 개선할 점

화면 구성은 [와이어프레임](wireframe.md)을 따릅니다.

- **119 버튼이 약합니다.** `main`은 높이 64dp의 빨간 버튼이지만 최신 앱은 연한 띠에 12~13sp 글자입니다. 안전 앱의 핵심 동작이므로 눈에 띄게 다시 설계합니다.
- **첫 화면에 인사말이 큽니다.** 인사말이 위쪽을 많이 차지하고, 안전 준비 카드가 첫 화면 아래로 밀립니다.
- **글자가 작고 대비가 낮습니다.** 보조 글자 `#7F8D83`의 대비는 배경 `#F5F7F3`에서 3.23:1, 흰색에서 3.48:1로 일반 글자 기준 4.5:1에 못 미칩니다. 10~12sp 지정도 52곳 있습니다. 야외 사용 기준으로 올립니다.
- **영어 제목이 섞여 있습니다.** `SAFETY CHECK`, `MAKE THE SITE SAFER` 같은 문구를 쉬운 한국어로 바꿉니다.
- **디자인 방향이 둘입니다.** `main`은 어두운 남색, 최신 앱은 밝은 녹색입니다. 브랜드 색은 관리자 웹과 함께 정합니다.
- **상태 표현을 통일합니다.** 정상, 주의, 긴급, 추정, 체험을 색에만 의존하지 않고 글자와 아이콘으로도 구분합니다.
