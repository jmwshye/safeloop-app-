## 팀 결정이 필요한 사항

### 1. 서버: NestJS로 통일 (2026-11-02 합의)

서버는 NestJS·PostgreSQL로 통일하고, 푸시 알림만 Firebase FCM을 씁니다. 안전 호출, 푸시, 사진, 위험 신고, 기록 보호, 보고서는 #7~#9에 옮겨졌습니다. 작업자 앱 연결은 #10에 있습니다.

**시연을 폰 2대로 하려면 아직 필요한 것**

- 서버를 올릴 곳과 두 폰이 열 수 있는 `https` 주소
- FCM 서버 인증 설정과 두 폰의 알림 수신 확인
- 시연용 계정 2개, 현장 코드, 안전 동료 배정
- 두 폰 모두 Android

개발 중에는 한 폰의 체험 모드에서 두 사람의 역할을 확인하고, 시연 때만 폰 2대를 씁니다.

**아직 정하지 않은 것:** 제출일, 서버를 올릴 곳, 관리자 웹을 NestJS로 옮길 담당.

### 2. 감지 기준 정하기

코드에 서로 다른 기준이 있습니다. 둘 다 실측값이 아닙니다.

| | `main` | 최신 앱 |
| --- | --- | --- |
| 충격 | 총 가속도 2.8G | 선형 가속도 약 3G (29.43m/s²) |
| 관찰 시간 | 3초 | 7초 |
| 판정 | 평균 움직임 0.45G 미만 | 관찰 시간의 70% 이상 1.5m/s² 미만 |

**최신 앱 기준으로 시작하고 실기기 측정 뒤 조정합니다.** #10은 고위험 작업 때 기준을 2.5G로 낮춥니다.

### 3. 코드와 헌장의 차이 정리

[프로젝트 헌장](https://claude.ai/artifact/QadKtQskLYTUSGinpBuT5c)과 [이전 화면 시안](https://claude.ai/artifact/Lz6o6yGJyZoNdL1Q1LpxB8)을 확인했습니다. 헌장은 아직 비공개이므로 팀 공유 여부를 정해야 합니다.

코드가 헌장과 다른 부분은 [와이어프레임 8장](wireframe.md#8-코드헌장과-다른-점)에 있습니다. 긴급 대응 사진은 NestJS에서 선택 항목입니다. 앱 화면이 같은 규칙인지 실기기에서 확인합니다.

### 4. 역할

민철은 기획·와이어프레임, 태규는 서버, 지혜는 작업자 앱을 맡습니다. 관리자 웹 담당은 아직 정하지 않았습니다.

## 코드에서 발견한 문제

`main` 코드의 문제는 최신 앱으로 교체하면 대부분 사라지므로 따로 고치지 않습니다.

| 위치 | 문제 | 처리 |
| --- | --- | --- |
| `main` `MainActivity.kt` | 119 버튼이 위치·로그를 즉시 전송한다고 표시. 실제로는 전화 화면만 열고 `EMERGENCY_119_CALLED`를 사람의 사실로 기록 | 교체로 해결 |
| `main` | 화면이 꺼져도 구조 요청한다는 안내가 있지만 포그라운드 서비스가 없음 | 교체로 해결 |
| `main` | 출근에 점검 3개가 필수라 백엔드·최신 앱의 규칙과 다름 | 교체로 해결 |
| `main` `SafetyModels.kt` | 해시가 메모리에만 있어 앱을 재시작하면 체인이 처음으로 돌아감 | 서버 해시 사용 |
| `main` | 실명, 고정 좌표, 고정 배터리 값이 코드에 있음. 이 저장소는 공개 상태 | 교체 후 이력 처리 여부 결정 |
| `main` | `app/google-services.json`이 공개 저장소에 있음 | Firebase API 키 제한 확인 |
| 관리자 웹 문서 | 사진 오프라인 큐, 동료 대칭 배정, 예정 체크인, 기기 미연결 감지, 보관·삭제 정책 미구현 | MVP 범위 결정 |

Firebase 웹·앱 키는 비밀번호와 달리 앱에 포함되는 값이지만, 보안 규칙과 키 제한이 없으면 악용될 수 있습니다. 서비스 계정 키나 서명 키가 공개되었다는 뜻은 아닙니다.
