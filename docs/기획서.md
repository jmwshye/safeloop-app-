# 안전고리 SafeLoop 기획서

2026-11-01 · [프로젝트 헌장](https://claude.ai/artifact/QadKtQskLYTUSGinpBuT5c) 요약

> 기준 문서는 헌장입니다. 이 문서와 헌장이 다르면 헌장을 따릅니다. 통계와 법령 내용은 헌장의 출처를 확인한 뒤 인용합니다.

안전고리는 민간 50억 원 미만 소규모 건설 현장을 위한 서비스입니다. 작업자는 자신의 근로와 부상을 증명하려고 앱을 쓰고, 그 과정에서 동료와 안전을 서로 확인합니다.

> 서로의 안전을 확인하면, 안전의 기록이 남는다.

## 1. 서비스 개요

### 해결하려는 문제

- **작업자의 증명 공백:** 다쳐도 `내가 그날 거기서 일했고, 거기서 다쳤다`를 증명할 기록이 부족합니다.
- **구조 공백:** 안전관리 인력이 상주하지 않아 쓰러진 사람을 늦게 발견할 수 있습니다.
- **서류의 실질 공백:** 일일 단위의 실제 이행이 요구되지만 소규모 현장의 서류는 사후 작성에 머물기 쉽습니다.

### 사용자

| 사용자 | 하는 일 | 사용 환경 |
| --- | --- | --- |
| 작업자 | 출퇴근, 작업 전 확인, 위험 신고, 본인 응답 | Android 앱, 작업 중 주머니에 휴대 |
| 안전 동료 | 보호구 교차 확인, 현장 확인 요청 처리 | Android 앱 |
| 현장 책임자 | 인원·위험·확인 현황 파악, 조치, 보고서 | 관리자 웹 |

### 핵심 가치

1. **작업자가 앱을 켤 이유:** 안전 앱이기 전에 내 근로 기록입니다.
2. **서로 확인하는 구조:** 본인 응답과 동료 확인을 나눠 혼자서 끝내지 못하는 상황을 보완합니다.
3. **사실과 추정의 구분:** 사람이 확인한 내용과 센서의 추정을 기록에서 분리합니다.

## 2. 서비스 흐름

### 하루 흐름

| 시점 | 작업자 | 시스템 |
| --- | --- | --- |
| 출근 | 출근 기록, 작업 전 3가지 확인, 동료 보호구 확인 | 근로 기록과 확인 결과 저장 |
| 작업 중 | 휴대폰을 몸에 휴대, 움직임 감시 시작 | 충격과 움직임 감소 감지 |
| 위험 발견 | 사진과 내용을 신고, 필요하면 익명 선택 | 조치 → 조치 후 사진 → 다른 동료 재확인 |
| 퇴근 | 퇴근 기록, 오늘 기록 확인 | 감시 종료, 근로 기록 마무리 |

### 안전 확인 흐름

| 단계 | 조건 | 동작 |
| --- | --- | --- |
| 1. 감지 | 큰 충격 뒤 움직임이 적음 | 본인에게 안전 확인 요청. 사고로 확정하지 않음 |
| 2. 본인 확인 | 15초 | 응답하면 오탐으로 기록하고 종료 |
| 3. 동료 호출 | 15초 무응답 | 지정 안전 동료에게 요청, 현장 책임자에게 동시 통보 |
| 4. 호출 확대 | 30초 무응답 | 같은 구역의 응답 가능한 작업자에게 요청 |
| 5. 현장 대응 | 동료 수락 | 도착 → 상태 확인 → 119·책임자 호출 → 정상 처리 |
| 6. 현장 사진 | 상황 안정 후 | 선택. 사람이 아닌 현장을 촬영 |

순서는 헌장 기준입니다. 현재 코드와 다른 점은 [와이어프레임 8장](wireframe.md#8-코드헌장과-다른-점)에 정리했습니다.

119는 모든 단계에서 사람이 직접 누릅니다. 사진이나 앱 절차가 구조를 늦추면 안 됩니다.

## 3. 기능 범위

### MVP

- 출퇴근과 예상 일당, 월별 근로 기록, CSV 내보내기
- 작업 전 3항목: 추락 위험 구역, 바닥·개구부·안전난간, 보호구
- 답변 3종: 확인, 개선 필요, 모름
- 안전 동료 2인 1조 배정, 사진 교차 인증, 불일치 처리
- 고위험 작업 모드, 체크인 요청
- 움직임 감시와 단계별 호출
- 위험 신고, 익명 선택, 조치 후 독립 재확인
- 안전 타임라인, 해시 기반 변경 탐지
- 보고서 3종: 작업자 근로 기록, 사고 경위 보고서, 월간 근로일·안전확인 집계
- 관리자 대시보드, 체험 모드

### 범위 밖

AI 보호구 분석, 사고 종류 확정, 정밀 층별 GPS, 자동 119 신고, 기관 직접 연동, 실지급 급여 정산, 채용 점수·순위, 워치 앱.

## 4. 제품 규칙

| 규칙 | 이유 |
| --- | --- |
| 센서 결과는 항상 추정으로 표시 | 휴대폰 낙하와 사람의 사고를 완전히 구분할 수 없음 |
| 119는 전화 화면만 열고 통화·접수로 기록하지 않음 | 실제 통화 여부를 앱이 알 수 없음 |
| 출퇴근과 안전점검을 분리 | 점검을 근로 기록의 조건으로 삼지 않음 |
| `모름`과 `개선 필요`도 정상 답변 | 형식적인 일괄 확인을 줄임 |
| 미확인을 사고로 표시하지 않음 | 작업자에게 불필요한 낙인을 남기지 않음 |
| 사진 없는 확인과 사진 인증의 등급을 구분 | 확인 수준을 기록에 드러냄 |
| 조치자·신고자가 아닌 동료가 재확인 | 스스로 완료 처리하는 일을 막음 |
| 원본을 고치지 않고 정정을 추가 | 사건 이력을 보존 |
| 익명 신고자의 식별 정보를 관리자에게 주지 않음 | 신고를 꺼리는 일을 줄임 |

## 5. 현장 사용성 기준

와이어프레임과 앱 구현에 적용하는 기준입니다.

- 장갑, 햇빛, 고령 작업자를 전제로 큰 터치 영역과 충분한 대비를 씁니다. 주 버튼 높이는 60 이상입니다.
- 작업 중에는 화면을 보지 않습니다. 긴급 알림은 진동·소리·잠금 화면으로 먼저 전달합니다.
- 작업자가 자주 하는 일은 적은 조작으로 끝납니다. 출근은 앱을 연 첫 화면에서 할 수 있어야 합니다.
- 모든 위험 화면에서 119와 현재 상태가 먼저 보여야 합니다.
- 전문 용어와 영어 제목을 피하고 쉬운 한국어를 씁니다.

화면별 기준은 [와이어프레임](wireframe.md)에 있습니다.
