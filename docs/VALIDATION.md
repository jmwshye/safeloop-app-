# 작업자 앱 검증

2026-10-29 · 개발 브랜치 `feat/app-worker-experience`

## 확인한 내용

- JDK 17 / Gradle 8.9 / SDK 35에서 `testDebugUnitTest assembleDebug` 성공.
- 유닛 테스트 10개 통과: 기존 기본 테스트 1개, 센서 조건 4개, 근로·안전 확인·CSV 규칙 5개.
- debug APK v2 서명 검증 통과. 배포용 서명은 아님.
- Pixel 7 / Android 15(API 35) 에뮬레이터에 설치하고 실제 실행.
- 오늘·안전·신고·기록·내 정보의 화면 이동과 하단 119 버튼 표시 확인.
- 점검 없이 출근 저장, 근로 기록과 예상 일당 합계 반영 확인.
- 본인 확인 알림 생성과 15초 카운트다운, 기한 내 응답에 따른 종료 확인.
- 15초 무응답 후 동료 응답 대기로 전환 확인.
- 동료 요청 수락 → 현장 도착 → 시스템 카메라 촬영 → 앱 사진 미리보기 → 직접 안전 확인 체크 → 사진 제출 → 완료 확인.
- 촬영 사진은 에뮬레이터의 가상 장면임. 실제 현장의 확인 자료가 아님.
- 앱 강제 종료·재실행 후 출근, 본인 응답, 무응답 전환, 동료 완료 상태와 사진 파일 보존 확인.
- 확인 중 앱의 `AndroidRuntime` 오류는 관측되지 않음.
- 119 버튼으로 전화 앱이 열리고 번호가 119로 입력되는 것 확인. 발신 버튼은 누르지 않음.

실행 검증에서 상세 창 제목과 상태 표시줄이 겹치는 문제를 발견해, 상세 창 내부의 높이를 제한하도록 수정했다. 수정 후 APK를 다시 빌드·설치했으며 상세 창이 상태 표시줄 아래에 열리고 닫기 버튼으로 기본 화면에 복귀하는 것을 확인했다.

## 관리자 웹

별도 `safeloop` 저장소에서 작업자 화면·역할 전환·작업자 웹 참여 폼을 제거했다. 기존 관리자 대시보드 디자인과 메뉴는 유지했다. 웹 프로덕션 빌드, Node 테스트 15개, 실제 Chrome의 관리자 메뉴 6개·초대 안내·작업자 전환 버튼 부재·콘솔 오류 부재를 확인했다. Firebase 함수 문법 검사도 통과했다.

## 아직 검증하지 않은 내용

- 실제 Firebase 배포 계정으로 로그인·현장 참여·규칙·Storage·Cloud Tasks·FCM을 연결한 통합 시험
- 여러 실제 작업자 기기와 관리자 웹 사이의 알림 수신·확인·사진 열람
- 실기기의 잠금 화면·절전·네트워크 단절·장시간 센서 동작·오탐과 미탐·배터리 사용량
- 실제 119 통화 연결: 전화 앱을 여는 구현이며 시험 통화는 하지 않음

현재 체험 모드의 성공을 실제 기기 간 푸시나 사고 감지 정확도의 검증 결과로 해석하면 안 된다. 근처 작업자는 기존 서버의 같은 작업 구역·응답 가능 여부로 선정하며 GPS 거리 기반 선정을 새로 구현한 것은 아니다.

노트북은 RAM 약 8GB다. 첫 에뮬레이터 부팅 때 Android 시스템 UI 응답 지연 창이 나타났고, 기다리기 선택 후 진행했다. 앱 런타임 오류와 구분한다. 이 PC의 GPU 충돌을 피한 실행 설정은 SwiftShader / Vulkan OFF / 스냅샷 OFF다.

원격 push·main 병합·Firebase 배포는 수행하지 않았다. Android Studio에서 최종 화면을 검토한 뒤 팀 규칙에 따라 진행한다.
